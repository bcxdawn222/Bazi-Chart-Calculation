# Proposal: wechat-miniprogram-reuse

## Why

两个 APK 已恢复出八字、紫微和时间处理相关页面，但 Android Java/XML 不能直接作为微信小程序运行。需要把已确认的页面职责、字段和可复用规则迁移为小程序原生工程，先形成可导入、可运行、可核验的核心版本。

## What

- 新建微信小程序工程骨架和输入页 | verify: 工程包含 `app.json`、`project.config.json`、输入页和结果页，目录检查通过
- 将 `base1.apk` 的八字输入、时间设置、排盘结果、紫微十二宫展示职责迁移到小程序页面 | verify: 页面包含出生日期、时间、地点、性别、阳历/农历、真太阳时和早晚子时输入，并能进入结果页
- 按恢复源码证据重写本地时间、八字和紫微计算模块 | verify: 计算模块可被页面调用，并返回四柱、十神、大运/流年、十二宫、主星/辅星和四化字段
- 复用 APK 中已确认的结果字段和阅读结构，采用单页分区展示 | verify: 结果页能展示八字、紫微、运势和解读区域，未引入 APK 范围外的业务模块
- 增加本地工程检查和最小计算验证入口 | verify: 使用项目脚本执行结构检查和固定样例计算，输出可复核结果

**Not in this change**: 不接入旧 SOAP/HTTP 服务和 APK 内密钥；不实现支付回调、AI 大数据服务、会员、收藏、聊天、六爻、奇门、文章和悬赏；不恢复原 Android Gradle 工程；不保证恢复源码中未确认的 native 算法与原产品结果完全一致。

## How

- 以 `base1.apk` 的 `BzInputActivity`、`BzTimeInput`、`BzShowForm`、`ZwView`、`ShiErGongView` 和对应布局作为第一迁移来源，以 `base.apk` 的业务入口和解读相关源码作为第二参考；证据与路径记录在 `research.md`。
- 在 `miniprogram/core/` 中重写纯 JavaScript 计算模块，在 `miniprogram/pages/` 中实现输入和结果页面；页面不直接依赖恢复目录。
- 采用本地样例和模块级断言核验输入归一化、四柱、十神、大运/流年和紫微十二宫结果；无法从恢复源码确认的计算分支保留明确状态。

## Risk

- 恢复源码存在混淆和 JADX 错误，部分规则可能只在 native 或旧服务端；通过证据标注和样例核验区分已确认与待核验结果。
- 小程序运行环境与 Android 不同，XML 布局和系统 API 不能直接搬运；通过职责映射和原生页面重写降低迁移风险。
- 未接入旧服务时，网络解读和支付内容暂时不具备生产能力；本次只交付本地核心流程，后续按客户确认的接口再扩展。
