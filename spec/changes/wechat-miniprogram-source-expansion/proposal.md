# Proposal: wechat-miniprogram-source-expansion

## Why

现有微信小程序已经完成基础八字和紫微排盘，但参考文档要求的均时差、藏干、纳音及更多紫微明细尚未覆盖。两份 APK 的恢复源码提供了部分字段、布局和规则线索，需要按证据强度补强本地算法，同时保持已通过的基础结果和页面流程不回退。

## What

- 修订正式 PRD 和 Phase 计划，明确当前源码补强范围、后续规则深化和商业化边界 | verify: Markdown 与 Word 版本内容一致，Word 正文字体为黑色，PRD 验收项和 Phase 依赖可逐项核对
- 完善真太阳时计算，增加均时差、修正明细和跨日处理 | verify: 固定日期和经度样例返回经度修正、均时差、总修正及最终时间，跨日后四柱使用修正日期
- 增加八字藏干、藏干十神、纳音和客观五行统计 | verify: 十二地支藏干和六十甲子纳音固定样例通过，四柱详情可由结果构建入口返回
- 增加有规则证据的紫微六吉六煞、星曜亮度和三方四正关系 | verify: 固定命盘的星曜分类、对宫与三合宫断言通过，没有规则证据的字段不伪造结果
- 更新单页结果展示并保持现有输入、八字、运势、紫微和解读流程兼容 | verify: 页面模拟可以提交输入、加载结果并读取新增明细，原有字段绑定继续通过
- 扩充自动检查脚本和日志，覆盖新增算法与回归基线 | verify: 通过 `python scripts\check_miniprogram.py` 执行，原有 599 组常规日期、55 组闰月和新增断言全部通过，结果写入 `logs`

**Not in this change**: 不实现旺衰、喜用神、八字格局、紫微格局和流月的未验证算法；不实现登录、支付、会员、AI、大师咨询、合婚、起名、择日、社区；不接入旧 APK 网络接口、密钥或历史服务器；不开发 Android App、H5 或桌面端。

## How

- 保留原生微信小程序和现有核心调用链，将均时差、八字明细和紫微明细拆入独立模块，现有接口只追加字段。
- `base1.apk` 用于核对藏干、纳音、神煞、十二宫和星曜展示，`base.apk` 用于核对真太阳时、喜用与解读入口线索；两份源码不视为同一套算法。
- 固定映射和可追溯规则直接实现；只有页面标签、没有计算链的内容保持为后续范围。
- 所有构建、检查和日志输出继续由 `scripts` 目录统一组织。

## Risk

- 均时差会改变接近午夜和子时边界的结果；通过修正明细、兼容字段和边界样例控制回归风险。
- 恢复源码存在反编译错误和流派差异；通过证据门槛避免把 UI 标签误当算法，并保留客户基准样例终验条件。
- 新增字段会提高结果页信息密度；通过分区、稳定布局和小屏检查避免文字挤压。
- 正式 AppID 和客户权威排盘样例仍是外部条件，本地测试通过不等同于最终业务口径确认。
