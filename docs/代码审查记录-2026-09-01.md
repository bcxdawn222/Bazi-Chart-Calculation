# 代码审查记录（2026-09-01）

## 审查范围

- 原生微信小程序页面、本地排盘模块、网络请求和本地记录同步。
- Python 标准库 HTTP 服务、SQLite 数据访问、微信登录、咨询订单和微信支付 API v3。
- 运营配置页面以及启动、测试、预览和清理脚本。

## 已处理问题

- 修复最近命盘把日期和时间写入同一字段，导致日期选择器无法恢复的问题，并兼容旧缓存。
- 公开接口只返回在线且已定价专家，以及未过期、未被预约的排班。
- 咨询订单必须绑定可用排班，并使用 SQLite 写事务阻止并发重复预约。
- 已有订单的排班禁止修改专家或时间，避免历史订单信息漂移。
- 订单付款、服务确认、服务完成和评价按明确状态顺序执行。
- 支付取消后复用已有预支付标识重新签名，不重复创建同一商户订单。
- 支付通知支持大小写不敏感的 HTTP 头，并校验通知、订单和微信交易号的唯一关系。
- 运营关闭咨询或支付后，后端接口同步拒绝请求，不只依赖页面按钮。
- 小程序请求增加超时、并发登录合并和中文错误提示。
- 祈福与心愿记录在云端操作成功后再修改本地状态，删除前增加确认。
- 咨询逻辑从工具页拆分为独立模块，工具页代码规模明显下降。
- 损坏或旧版本命盘缓存会清除并提示重新排盘。
- API 增加请求体限制、安全响应头、有限列表和过期会话/限流记录回收。
- SQLite 连接在提交或回滚后明确关闭，避免 Windows 和长期服务中的数据库句柄泄漏。
- 公开排班在 SQL 层排除过期及同一专家重叠时段；订单创建也按专家时段检查占用。
- 已发起支付的订单不能直接取消；旧异常状态收到可信支付通知时恢复为待确认服务。
- 服务或支付未就绪时后端拒绝创建订单，同一用户同时只保留一笔未支付有效订单。
- Caddy 代理后的限流使用经校验的 `X-Forwarded-For`，外部直连不信任伪造头。
- 运营页增加接口地址校验、非 JSON 错误处理、防重复提交和状态化订单操作。
- 运营动态操作增加确认、防重复提交和错误反馈。
- 支付重试每次重新向后端获取签名参数；页面隐藏时停止轮询，返回后刷新咨询数据。
- 部署与运维脚本默认拒绝未知 SSH 主机密钥，恢复路径不能越出备份目录。
- 测试脚本输出到日志，并提供安全清理缓存和失效 PID 的命令。

## 外部终验项

- 正式发布地址仍需在小程序运行配置中填写备案 HTTPS API 域名。
- 正式微信登录、商户参数、证书和真实扣款回调需要生产资质与真机环境验证。
- 退款流程不在当前交付范围，已支付订单不会由运营页直接取消。
