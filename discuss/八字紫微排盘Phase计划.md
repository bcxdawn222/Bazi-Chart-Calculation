# 八字紫微排盘微信小程序 Phase 计划

## 1. 计划说明

本计划以客户需求、参考文档、两份 APK 恢复源码和当前微信小程序工程为依据。开发采用“先保留已通过的基础排盘，再按源码证据补强字段”的顺序。

本轮在基础排盘上增加参考图红圈中的本地测算、祈福和咨询入口。咨询订单、专家排班运营接口、订单回查和微信支付 API v3 服务端流程已接入；生产参数和真实交易仍需外部终验，会员、AI、深度报告和完整履约后台不在本轮范围。

## Phase 0：源码恢复与基础版本

状态：已完成，保留为开发基线。

工作内容：

- 完成 `base.apk` 与 `base1.apk` 的静态分析和运行时恢复。
- 建立微信小程序原生工程。
- 实现阳历/农历、闰月、经度近似真太阳时和早晚子时。
- 实现八字四柱、十神、大运、流年和部分神煞。
- 实现紫微十二宫、主辅星、四化、大限和流年命宫。
- 建立自动检查脚本和页面流程模拟。

阶段产出：

- 可导入的微信小程序基础工程。
- APK 恢复源码与分析报告。
- 基础排盘自动检查日志。

## Phase 1：PRD、规则台账与验收样例

目标：确定本次源码补强的字段、证据和验收口径。

工作内容：

- 更新微信小程序 PRD 和 Phase 计划。
- 建立字段与恢复源码文件的对应关系。
- 区分“已有完整规则”“只有页面字段”“需要客户样例”的内容。
- 固定现有 599 组常规日期、55 组闰月和页面流程回归基线。
- 准备真太阳时、子时跨日、节气切换、藏干、纳音和紫微星曜样例。

阶段产出：

- 正式 PRD。
- Phase 计划。
- 源码证据与验收规则台账。

## Phase 2：时间与八字字段补强

目标：完善真太阳时和八字基础结果，不改变现有输入流程。

工作内容：

- 将真太阳时由经度近似修正升级为经度修正加均时差修正。
- 展示原始时间、两类修正分钟和最终采用时间。
- 实现十二地支藏干和藏干十神。
- 实现六十甲子纳音。
- 实现可复核的五行数量统计。
- 扩充有源码或规则表依据的神煞。
- 保持四柱、十神、大运和流年现有接口兼容。

阶段产出：

- 时间修正模块。
- 八字明细模块。
- 新增字段固定样例测试。

## Phase 3：紫微字段补强与结果页调整

目标：补充源码可追溯的紫微字段并完成结果展示。

工作内容：

- 补充六吉星和六煞星安星结果。
- 补充有规则表依据的庙、旺、利、陷状态。
- 计算并展示三方四正宫位关系。
- 保留十二宫、主辅星、四化、大限和流年现有结果。
- 在单页结果中增加八字明细和紫微明细区域。
- 对小屏幕文字换行、宫位信息密度和滚动阅读进行检查。

阶段产出：

- 紫微明细模块。
- 更新后的结果页。
- 页面字段绑定检查结果。

## Phase 4：回归测试与微信开发者工具验收

目标：确认新增字段没有破坏基础排盘能力。

工作内容：

- 通过 `scripts` 目录统一执行结构、算法和页面流程检查。
- 重跑现有常规日期、闰月、节气切换、大运和紫微回归用例。
- 增加均时差、跨日、藏干、纳音、六吉六煞和三方四正测试。
- 使用微信开发者工具检查工程导入、编译和页面渲染。
- 输出日志、测试结果和待客户确认项。

阶段产出：

- 自动检查日志。
- 微信开发者工具验收记录。
- 客户基准样例待确认清单。

## Phase 5：规则深化

启动条件：客户提供认可的规则、样例或专业人员确认结果。

工作内容：

- 五行旺衰。
- 喜用神。
- 八字格局和紫微格局。
- 流月。
- 更完整的命理解读规则。

阶段产出：

- 经样例验证的深化算法。
- 深化算法回归测试集。

## Phase 6：红圈本地测算扩展

目标：把红圈中的每日运势、财富运程、六爻/求卦、合婚和名号功能落到可操作页面。

工作内容：

- 增加每日运势和 2026 财富运程入口，读取现有命盘结构化字段。
- 按恢复源码时间起卦口径增加六爻排盘和有事求卦。
- 增加八字合婚双方输入、命盘摘要和结构化关系提示。
- 增加名号测算输入、自动康熙笔画查询、五格接口和缺字提示。
- 记录康熙笔画数据源、MIT 许可、导入脚本和常用字覆盖量。
- 增加固定样例和输入边界检查。

阶段产出：

- 工具页及本地测算核心模块。
- 六爻、合婚和名号状态可复核的检查结果。

## Phase 7：祈福与咨询入口

状态：已完成，已增加本地模式与后端同步模式。

目标：完成祈福明灯、祈福好运/心愿阁和真人在线 1v1 的可操作流程。

工作内容：

- 增加祈福明灯和心愿阁本地记录。
- 支持创建、查看、标记完成和删除心愿。
- 增加真人在线 1v1 微信客服入口。
- 在页面中区分本地记录与线上服务、支付和订单状态。
- 增加用户会话、记录归属、远端列表、状态更新和删除接口。
- 增加专家、排班、咨询订单和公开运营配置数据结构。

阶段产出：

- 祈福页。
- 微信客服入口、专家排班选择和最近订单状态页面。

## Phase 8：商业化功能

状态：咨询订单与微信支付代码已完成；待客户提供生产参数并进行真机真实回调验证。会员、AI 和深度付费报告不在本轮范围。

启动条件：客户确认咨询价格、主体资质、支付流程并提供正式微信参数。

工作内容：

- 微信登录和咨询订单。
- 微信支付：JSAPI 下单、小程序调起、API v3 通知验签解密、金额校验、幂等更新和支付状态展示。
- 专家和排班最小运营配置、订单查询和服务状态更新。
- 客户确认后的专业规则和收费内容。

阶段产出：

- 经确认的商业化版本。

## 依赖关系

- Phase 1 是本次开发入口。
- Phase 2 与 Phase 3 均依赖 Phase 1 的字段和样例口径。
- Phase 4 依赖 Phase 2 和 Phase 3 完成。
- Phase 5 依赖客户认可的规则或基准样例。
- Phase 6 依赖现有排盘结构和本地工具页框架。
- Phase 7 依赖微信客服能力和本地存储页面流程。
- Phase 8 依赖正式小程序 AppID、微信支付商户资质、证书、API v3 Key、HTTPS 通知地址和客户确认的价格与付费内容。

## 当前交付边界

当前计划执行到 Phase 10 的生产准备验收。Phase 8 的微信支付代码已进入工程，但未作为真实交易完成承诺，生产参数和真实扣款仍待外部验证。

## 本轮范围约束

- 只实现参考图红圈的 10 项：八字排盘、每日运势、祈福明灯、有事求卦、六爻排盘、八字合婚、财富运势/2026 财富运程、批 2026 好运/真人在线 1v1、名号测算、祈福好运/心愿阁。
- 不增加未圈出的婚姻树、好运福袋、一生财运、招财树等功能。

## Phase 9：后端部署与交付验收

状态：已完成服务器内部部署、服务重启、健康检查、数据库备份恢复和运营配置页部署；公网接入待腾讯云控制台配置。

工作内容：

- 在 Ubuntu 服务器用户 `ubuntu` 下部署后端服务和 SQLite 数据库。
- 配置 `systemd` 服务守护和 Caddy 反向代理。
- 完成后端状态、健康检查、服务重启、数据库备份和恢复验证。
- 使用服务器端环境文件保存会话密钥和运营令牌，不写入源码、日志和交付文档。
- 部署 `/admin/ops-config.html` 运营配置页，支持维护专家和排班、查看订单及更新服务状态，支付状态保持只读。
- 生成 Windows 与 Linux/macOS/WSL 两类运维脚本入口。
- 整理 PRD、Phase、部署说明、运行说明、待配置清单、测试日志和交付包。
- 配置公网访问前，需要补充腾讯云安全组 HTTP/HTTPS 端口、备案域名、TLS 证书和微信服务器域名白名单。

阶段产出：

- 后端部署和运维脚本。
- 服务器健康、重启、备份恢复验证日志。
- 客户运行说明和待配置清单。

## Phase 10：生产准备流程完善

状态：代码与自动检查已完成，正式微信登录、备案 HTTPS 域名和真实支付保留为外部终验项。

工作内容：

- 修正微信支付 API v3 官方通知结构解析，校验 AppID、商户号、金额、币种和通知幂等。
- 增加显式 HTTPS API 地址配置；未配置时保留本地功能并显示 `local-mode` 原因。
- 增加受 `ADMIN_TOKEN` 保护的专家、排班和订单运营接口与页面。
- 增加用户单笔订单查询、最近订单、支付后有限轮询和手动刷新。
- 补齐每日运势五项、合婚时间口径和名号关联最近命盘字段。
- 固定康熙笔画数据来源版本并随交付包提供 MIT NOTICE。
- 部署脚本增加 `.venv` 依赖安装、Caddy 配置备份验证和域名 HTTPS 模式。
- 更新 PRD、Phase、Word、客户 TXT 说明、测试日志和交付压缩包。

阶段产出：

- 可配置生产 HTTPS 地址的微信小程序工程。
- 最小运营页面和咨询订单状态流程。
- 自动化测试、部署配置测试、第三方 NOTICE 和交付包。
- 正式 AppID、商户参数、证书、备案域名和真实交易外部终验清单。
